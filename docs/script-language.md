# Script Language

The timestamped script is the source of truth. Short syntax is primary; legacy long
commands remain accepted. The user-facing syntax table is in
[README.md](../README.md#script-syntax). `src/lib/commands.ts` is the catalogue: each command's words (token and long alias),
argument parser, and the prose the insert menu and the Text view's syntax hint show.
`src/lib/timeline.ts` owns the line shape and timestamps and dispatches to it. A new
kind's syntax is one catalogue entry plus its `EventFields` variant; the compiler then
names every exhaustive table and switch that must handle it.

## Parser Rules

- When changing parser behavior, return visible `TimelineEvent` errors rather than silently ignoring malformed script input.
- The errors band reports in script order, not in the order errors happened to accumulate: `buildWorld` sorts `scriptErrors` by line before returning, because the band is read (and announced by `role="status"`) against the text the author is about to go fix. It shows `ERRORS_COLLAPSED_ROWS` rows and collapses the rest behind a count rather than becoming a fixed-height scroll region inside an already-scrolling panel.
- When changing chess behavior, add conservative validation rather than accepting ambiguous or typo-like SAN.
- SAN capture markers must match the resolved move. `Nxe5` should not resolve to quiet `Ne5`, and quiet SAN should not hide a capture.
- Standard SAN and FEN resolution follows the pinned `chess.js` version. Gambit strips its four quality marks (`!!`, `!`, `?`, `??`) before strict SAN parsing; chess.js owns check/mate suffix normalization, rejects zero/lowercase castling notation, and fills omitted trailing FEN fields. Beyond chess.js, `stateFromFEN` rejects three positions chess.js loads on trust, because each lets a scripted move disturb a piece Gambit's board never placed: the side not to move already in check, a castling right without its king and rook on their home squares, and an en-passant square with no pawn that just passed it. Rejected, not repaired — they read as typos.
- Timestamp parsing must never produce `NaN`; invalid timestamps should become script errors.
- Highlight and arrow square inputs should be validated before reaching `Board`.

## Command Semantics

- `reset` should restore the configured Start FEN; `start` should restore the standard initial chess position. Both clear transient visuals such as capture flash, arrows, highlights, and last move.
- Branch/mainline snapshots should restore board state and overlays without mutating prior snapshots.
- `br`'s timestamp is ordering-only: it renders nothing, so any value between the neighboring events is equivalent. `ml`'s timestamp is meaningful — it is the visible moment the board starts returning to the main line: branch-moved pieces glide home from where the branch left them and branch-captured pieces fade back in, all clock-derived from the `ml` timestamp (pieces a mid-branch setup re-minted still hard-cut). UI should let users edit `ml` times but not surface `br` times as editable.
- Mainline replay (`rp`, alias `replay`) is derived from all successfully applied preceding top-level moves and runs at 0.5s per move by default; `rp <seconds>` overrides the per-move step (0.1–10 seconds, one decimal place — anything else is a parse error; only the step is on the decisecond grid, while the authored start keeps its full precision). Exclude every move at any `br` / `ml` depth and every rejected SAN; honor top-level `rs`, `st`, and valid `fen` setups between moves without allocating them a time slot. A trailing setup may hold a position for explanation before `rp`, but replay ends on its last eligible move; subsequent commands and replay templates continue from that position. Replay clears overlays, extends playback duration at the tail, and drives Present's current PGN pill through existing source moves without duplicating rows. Disable board gestures while replay is active. Reject replay visibly if it is inside a branch, has no eligible move, occurs during `mind`, exceeds the playback ceiling, or would end after the next authored event; ending exactly on the next timestamp is valid.
- A question card (`ask <seconds> <question>`) takes the seconds first, a whole number from 1 to 30, so the question itself may start with a digit; a missing question, a missing or non-integer count, or one out of range is a parse error naming `ask`. The card is not board state and the snapshot walk does not carry it: `activeAskAt` reads the latest reached `ask` off the events and shows it while `time < t + seconds`. A later `ask` replaces an earlier one outright, even when it expires first; no other event ends a card, and `br`/`ml` do not restore one. The walk only extends `visualEndTime` to the countdown's end, so a card that outlasts the script holds the playback tail.
- Mind's-eye mode (`mind` … `reveal`) renders the narrator's mental sketch: the board sinks into a near-black void (grid nearly invisible, coordinates swap to a bright ink and stay fully legible) and only squares the script has named show pieces — a move names its from/to squares, the captured square, the castling rook's path, and the checked king; `hl` and arrows name their squares. Named pieces fade from full strength to nothing on a forgetting curve — what isn't restated is forgotten — except rehearsed squares, which hold at full strength: the move currently on the board (held until the next move takes over, since the gap between moves outlasts the curve and the narration is still on that move) and squares under a currently-visible highlight or live check (arrows name their squares like anything else, but never rehearse them — a named arrow square forgets on the curve from the instant the arrow was drawn). Rehearsal that ends at an event is released — the squares are named again at that instant, so they forget from there rather than popping out: the outgoing move when the next one takes over, a pinned highlight when `cl` clears it, the checked king when a move answers the check. An unpinned highlight expires between events, where the walk has no instant to name, but it only ever holds a piece for its own 2.5s. `rs`/`st`/`fen` empty the sketch while staying dark; `reveal` lifts the mode with a deterministic fade-in. The whole thing is derived state (events + time): the touch map and the held set are computed in the snapshot walk, so br/ml restores them like any other board state, and the void's depth is a clock-derived layer opacity rather than a CSS transition — script + FEN + time fully determine every frame, including mid-sink ones.
